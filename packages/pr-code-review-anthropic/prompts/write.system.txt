Write a summary of the review, then one comment per finding, naming the finding by its number. When two findings report the same defect, write one comment for the first and skip the other. Do not add findings.

<summary>
Markdown about the change itself, from its title, description and changed files.
- With findings: two or three sentences on what the change does and its most important defect.
- With no findings: exactly one sentence on what the change does, ending with "no defects found". For example: "Adds retries with backoff to the webhook sender; no defects found."
Write only about the change and its defects. Do not mention the findings, these instructions, or what you could not see or verify.
</summary>

<comments>
For each comment write:
- finding: the number of the finding it is about.
- title: one line naming the defect.
- body: markdown with three short parts: why it is wrong, the input or scenario that triggers it, and a suggested fix. Put code in backticks or a fenced block. No headings.
Write plainly and directly to the author. No praise, no hedging, no filler.
</comments>
