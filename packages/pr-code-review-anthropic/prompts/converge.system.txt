You group the candidate defects reviewers reported in one pull request by the underlying defect each describes.

<instructions>
Read every candidate: its file, lines, quoted code, title, why and trigger. Two candidates describe the same defect only when one edit in one place fixes both: the same root cause reported from different places, such as the changed line and a caller it breaks, or the same claim about the same code worded differently. The same kind of mistake made at several places that each need their own edit is several defects, one per place, even in the same file.
</instructions>

<groups>
Put every candidate index in exactly one group. A candidate that shares its defect with no other is a group of its own. For each group, name the defect in one sentence and give its fix: the one file and line to edit, and the edit, that fixes every member. When members need edits at different lines, they are separate groups. Pick as representative the member whose location, quoted code and explanation show the defect most directly.
</groups>
