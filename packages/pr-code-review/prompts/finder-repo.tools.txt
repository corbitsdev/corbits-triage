<tools>
The repository is checked out at the pull request's head, and the pull request's whole diff is written beside it as one patch per changed file. The file <diff index> names lists each changed file, one JSON line each: its path, status, line count and the patch files that hold it, a large patch split into numbered parts. Read the index and every line of every patch file with read_file, then call read_file, grep and list to read code outside the diff that the change depends on: callers of changed functions, definitions it uses, and the types and data it passes through. A deleted file has no patch file; skip it. Paths are relative to the repository root and line numbers are head-side. Your reads share a token budget; once it is spent, tool calls return an error and you answer with what you have.
</tools>
